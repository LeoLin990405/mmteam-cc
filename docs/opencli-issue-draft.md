## Issue draft #1 — "Add Trae SOLO and Qoder.app to Electron App adapters"

**Title**: `[adapter request] Trae SOLO + Qoder.app — two missing Chinese-market AI IDE Electron apps`

**Labels**: `enhancement`, `adapter-request`, `electron-app`

**Body**:

```markdown
## Background

opencli v1.8.0 ships native Electron app adapters for 7 desktop apps (antigravity / chatgpt-app / chatwise / codex / cursor / discord-app / doubao-app). Two widely-used AI coding IDEs are missing:

- **Trae SOLO** (ByteDance, `com.trae.solo.app` v0.1.14, VSCode fork)
- **Qoder** (Alibaba, `com.qoder.app` v1.106.3+, VSCode fork — has both a desktop app and a separate `qodercli` AI terminal)

Both are Electron apps that respond to `--remote-debugging-port=N`, so the CDP foundation already works. What's missing is the chat-DOM driver (the layer Codex/Cursor adapters provide).

## Why it matters

Users in the Chinese AI dev ecosystem rely on Trae SOLO and Qoder as their primary IDEs (analogous to how western users rely on Cursor). Without adapters, they have to fall back to generic `opencli browser` + manual CSS selectors, which is fragile (UI updates break it) and won't share code across users.

## Proposal

Add two new adapter directories with the standard 8 commands mirroring `clis/cursor/`:
- `clis/trae-solo/{status,new,read,send,ask,extract-code,history,model}.js`
- `clis/qoder/{status,new,read,send,ask,extract-code,history,model}.js`

Register both in `src/electron-apps.js`:
```js
'trae-solo': { port: 9235, processName: 'TRAE SOLO', executableNames: ['Electron'], bundleId: 'com.trae.solo.app', displayName: 'Trae SOLO' },
qoder: { port: 9237, processName: 'Qoder', executableNames: ['Electron', 'Qoder'], bundleId: 'com.qoder.app', displayName: 'Qoder' },
```

Ports 9235/9237 avoid collision with existing entries (9222 cursor, 9224 chatwise, 9225 doubao, 9230 codex, 9231 chatgpt, 9232 discord, 9234 antigravity).

## Volunteer

Happy to submit PRs for both after first wave of selector reverse-engineering (issue tracker is fine for coordination — leave comment to claim one or both).

## Related

- [PR #?? — `trae-solo` adapter — TODO]
- [PR #?? — `qoder` adapter — TODO]
```

## Issue draft #2 — "Antigravity CDP port should be configurable"

**Title**: `[bug] Antigravity CDP port hardcoded to 9234, breaks when user starts Antigravity on 9333`

**Labels**: `bug`, `antigravity`

**Body**:

```markdown
## Repro

1. Launch Antigravity with `--remote-debugging-port=9333` (Antigravity's documented default per Google forums)
2. Run `opencli antigravity status`
3. Expected: connects on 9333
4. Actual: probes 9234 only, fails with "CDP not available on port 9234 after 15s"; tries to restart Antigravity (won't help if user already configured 9333 deliberately)

## Root cause

`src/electron-apps.js` line 9-15 hardcodes `port: 9234`. The probe-and-restart logic in `src/launcher.js` lines 150-205 has no way to read user override.

## Suggested fix

1. Read `ANTIGRAVITY_CDP_PORT` env var as the highest-priority override
2. Read `~/.opencli/apps.yaml` `antigravity.port` as second-priority override
3. Fall back to hardcoded 9234 default

Same pattern for other Electron app entries (cursor 9222, codex 9230 etc) — port collision in multi-app setups is a recurring user pain point.

## Volunteer

Happy to PR after a quick API discussion in this issue (e.g., do we want a single `OPENCLI_<APP>_PORT` env var family, or YAML-only?).
```
